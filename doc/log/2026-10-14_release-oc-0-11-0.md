# Summary

## Objective
Livrer le binaire Rust (parité atteinte) aux utilisateurs sans Node.js, et rassembler dans ce dépôt la documentation produit qui était dispersée ailleurs.

## Problem
- La doc produit (port Rust, QA, conception de la CLI, bloc injecté, historique) vivait hors du dépôt, et une partie du dépôt public citait des chemins et projets privés.
- `migrate` était la seule commande non portée en Rust : la garder imposait de conserver Node pour une seule commande.
- Aucune chaîne de distribution du binaire n'existait (npm servait encore la 0.9.0 Node).

## Solution
- **Doc** : 8 refs nouvelles dans `doc/ref/` (CLI, MIGRATION, BLOC_INJECTE, HISTORIQUE, RUST_PORT, QA_INSTALL, QA_ONBOARDING, INSTRUCTION_FILES_AUTOLOAD), condensées depuis l'historique plutôt que de traduire les anciens logs ; refs et logs existants traduits ; règle « docs en français, code en anglais ». Mentions internes retirées des fichiers publics.
- **Issues** : 8 frictions du format ouvertes sur GitHub (#1 à #8) ; nouvelle commande `/oc-raise` pour en ouvrir d'autres depuis un agent.
- **`migrate`** : obsolète et désactivée ; Node et Rust affichent le même message (SSOT `templates/embedded/migrate-deprecated.txt`) qui renvoie vers `npx openclew@0.9.0 migrate`, dernière version qui la livre.
- **Distribution** : cargo-dist utilisé comme outil local (`dist-workspace.toml`, workspace Cargo remonté à la racine) ; la CI GitHub (release et tests) est supprimée, décision du mainteneur. Release `v0.11.0` créée avec `gh release create` : binaire Windows + `openclew-installer.ps1`, testés par une installation réelle dans un dossier temporaire.

# Details

## Choix et raisons

| Choix | Raison |
|---|---|
| Condenser en refs, pas traduire les logs | Les logs historiques étaient longs et datés ; le savoir durable tient dans quelques refs à jour |
| Installeur npm de cargo-dist (pas le modèle esbuild) | Zéro code à maintenir ; limite acceptée : le binaire est téléchargé depuis la GitHub Release à l'installation |
| Tags `vX.Y.Z` | Format attendu par les installeurs cargo-dist (`releases/download/vX.Y.Z`) ; `oc_` reste pour nommer les versions dans la doc |
| Aucune CI | Décision du mainteneur ; chaque OS construit ses binaires en local |
| Homebrew reporté | Exige un dépôt `openclew/homebrew-tap` et un token ; noté dans `TODO.md` |

## Contraintes mesurées

- Depuis Windows, `dist build` refuse de compiler pour macOS (« Cross-compilation … is not supported ») : les binaires macOS se construisent sur un Mac.
- Le paquet npm généré (`openclew-npm-package.tar.gz`, 17 Ko) ne contient aucun binaire : à l'installation il télécharge celui de la plateforme depuis la Release. Le publier avant que toutes les archives soient en ligne casse `npx openclew` sur les plateformes manquantes ; il n'est donc pas encore publié.
